# V3 整库认证与安全升级

V3 沿用 PBKDF2-HMAC-SHA256、不可导出 AES-256-GCM 密钥，以及逐条记录和分类加密。新增整库认证与经过认证的快照序号，用于检测删减、插入、重复、换序、拼接旧记录和外层元数据修改。同步 API 的 `protocolVersion` 保持 2，密文的 `formatVersion` 可以是 2 或 3。

## 信封与认证

V3 在原有字段上新增两个必填字段：

- `snapshotSequence`：从 1 开始的安全整数；每次编辑、主密码轮换或显式历史恢复生成新快照时递增。
- `integrity`：包含随机 96-bit IV 与 AES-GCM 密文/128-bit 认证标签的密文块。

生成 `integrity` 时，使用当前密码库密钥加密固定字符串 `AEGIS_V3_SNAPSHOT`。AAD 为 UTF-8 编码的 `aegis-v3:snapshot:` 加上整个信封去除 `integrity` 字段后的规范 JSON。规范化递归按对象键的字典顺序排序，保持数组顺序，数字和字符串采用 ECMAScript `JSON.stringify` 表示，不进行 Unicode 归一化。实现位于 `shared/vaultEnvelopeSchema.ts`。

认证覆盖版本、库标识、时间戳、KDF、cipher、verifier、加密分类、完整加密记录数组和快照序号。V3 的逐条记录、分类和 verifier 同时使用带有版本 3 的 AAD，删除外层认证字段并改成 `formatVersion: 2` 不能使其作为 V2 解密。每次加密都使用新的随机 IV。

结构检查会拒绝未知字段、缺失认证信息、重复记录 ID 和非法序号。解锁先验证主密钥，再验证整库认证，全部通过后才返回解密记录。

## 本设备的旧快照检测

IndexedDB 保存两类独立于云端响应的最高序号：本地已提交序号和已验证的远端序号。成功上传或认证并采用远端快照后，远端检查点取已观察序号的最大值。

- 远端回放低于检查点的有效旧密文会被拒绝，即使服务端声称有更大的 `revision`。
- 本地未同步修改不会提前提高远端检查点，因此正常落后于本地的云端快照仍可进入冲突确认流程。
- 两台设备从同一版本各自编辑可能产生相同序号；内容不同会进入冲突处理。选择保留本地时，重新认证为更高序号后再执行云端 CAS。
- 显式从备份或云端历史恢复，会创建新的认证快照，不修改旧快照的已认证时间戳。旧备份的读取能力被保留。

**限制：首次使用的新设备、清空浏览器数据后没有检查点的设备，以及本地执行环境已经被控制的情况，不能依靠这些检查点证明服务端返回的是全局最新快照。** 它们不构成跨设备的独立可信日志，也无法发现设备从未见过的新版本被隐瞒。V2 本身仍不提供整库完整性认证。

## 本地事务与并发

正式保存先在 IndexedDB 的同一 `readwrite` 事务内比较用户编辑时的完整快照和重置代数，再写入密码库、同步状态、检查点与必要备份。事务完成后才更新 localStorage 镜像并广播。

支持 Web Locks 时，同源标签页共享写入锁；不支持时仍依靠 IndexedDB 事务内的 CAS 拒绝过期写入。锁定、恢复确认、主密码轮换和普通编辑都不会授权覆盖后续发生的新修改。打开的旧表单发生冲突时保留内容，提示用户重新打开记录并合并。

IndexedDB 失败时，持久化的旧数据和镜像保持不变，当前会话保留加密候选及原始比较基线，支持导出和安全重试。仅镜像失败时，已提交的 IndexedDB 数据仍是权威副本。磁盘配额耗尽时不能承诺刷新后仍保存未提交内容，用户应先导出加密备份。

## 升级和部署顺序

1. 先更新 Worker。它兼容 V2/V3，并在 SQLite 事务中迁移旧 `format_version = 2` 约束；已有数据和云端 revision 保留。
2. 更新所有需要使用该密码库的客户端。新建库默认 V3；已有 V2 库继续可读、可编辑。
3. 在 V2 密码库解锁后的升级横幅点击“备份并升级到 V3”。原 V2 密文备份与 V3 替换在同一事务中提交；事务失败时原库保持不变。
4. 导出升级前备份，检查记录，然后同步云端。云端一旦接受 V3，将拒绝旧客户端上传 V2 覆盖该库。

升级不会更改主密码、vaultId、创建时间、记录内容或分类。V2 备份在 `vault_store` 的 `legacy_v2_backup` 键保存，并可从界面导出。主密码轮换不会删除已有导出文件和旧密码加密的备份。

## 验证

- 冻结的真实 V2 算法合成夹具验证兼容读取与迁移。
- 单元/集成测试覆盖整库篡改、空库、轮换、SQLite 约束迁移、两设备冲突与检查点回放。
- IndexedDB 事务测试覆盖同基线竞争、事务中止、镜像清除、备份原子性、过期恢复确认及重置后写入。
- Chromium 测试覆盖显式升级与失败重试、离线重新解锁、旧表单冲突、未提交内容加密导出、镜像故障恢复和无 Web Locks 的双标签页竞争。

```sh
npm ci --legacy-peer-deps
npm test
npm run lint
npx playwright install --with-deps chromium
npm run test:e2e
```

浏览器测试只使用合成凭证。CI 同时运行单元测试和 Chromium 回归，失败时保留七天测试追踪。
